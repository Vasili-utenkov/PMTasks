##### Контекст и цифры
Компания переходит с нескольких таблиц Excel на готовую кадровую систему. 
Нужно перенести карточки 750 сотрудников: ФИО, подразделение, должность, дату приёма, рабочий график и остаток отпуска. 
Список полей, правила заполнения и шаблон итогового отчёта согласованы с HR. 
Переход должен состояться в выходные 26–27 октября, чтобы с понедельника кадровики работали только в новой системе.
Перед запуском HR должен сверить выборку из 50 карточек, а бухгалтерия — получить отчёт по отсутствиям. 
В новом решении не должно быть карточек без подразделения или даты приёма. 
Исходные таблицы содержат персональные данные, поэтому доступ к ним есть только у согласованной группы сотрудников.


==Ограничения и допущения==. 
_Ограничения_
- Миграция должна быть проведена в выходные 26–27 октября
- Определена целевая система кадрового учета
- Определен список полей карточек для переноса и правила их заполнения
- Определены критерии целостности данных
- Определен шаблон итогового отчета по миграции

_Допущения_
 - Сотрудники HR будут доступны для проверки данных
 - Бухгалтерия предоставит недостающие данные
 - Исходные данные в Excel будут доступны и будут заблокированы на изменения на период миграции данных
 - Целевая система готова принять данные по согласованному шаблону
 - В период миграции не будет сбоев инфраструктуры
 - Сотрудник СБ проверяет формируемые в ходе выполнения работ отчеты на содержание в них чувствительных или критичных данных


==Критерии успеха==.  
- Успешная сверка данных: HR должен сверить выборку из 50 карточек
- Целостность данных подтверждена актом приемо-сдаточных работ
- Составление для бухгалтерии списка сотрудников.
- Процент не перенесенных данных не превышает целевой параметр
- С понедельника работа ведется в целевой системе. Откат данных не понадобился

##### US-001. Как _HR_ я хочу _получить выборку из 50 случайных карточек, прошедших миграцию_ что бы _убедиться в точности переноса_
Acceptance Criteria
- Получено 50 случайных карточек
- В выборке нет карточек с расхождениями
Приоритезация: _Must have_

==ЧЕК-ЛИСТ==

| Что проверяем                   | Ожидаемый результат                                | Статус      |
| :------------------------------ | :------------------------------------------------- | :---------- |
| Количество выбранных карт       | Количество ровно 50 штук                           | Пройдено    |
| Отсутствие карт с расхождениями | Карт с расхождениями данных не выявлено            | Пройдено    |
| Выборка должна быть случайной   | При каждом запуске выборки, состав карточек разный | Не пройдено |
|                                 |                                                    |             |

==БАГ-РЕПОРТ==

| Поле                      | Заполненный пример                                                                                                                                       |
| :------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Название**              | Выборка карточек одинаковый при каждой выгрузке                                                                                                          |
| **Шаги воспроизведения**  | 1. Нажать на выгрузку карточек и сохранить ее в файле<br>2. Повторно нажать на выгрузку карточек и сохранить ее в файле<br>3. Сравнить содержимое файлов |
| **Ожидаемый результат**   | Содержимое файлов должно отличаться друг от друга                                                                                                        |
| **Фактический результат** | Содержимое файлов одинаковое                                                                                                                             |
| **Приоритет**             | Высокий: Так как не исключен вариант, что заказчик захочет проверить дважды-трижды, новая проверка должна проводится на новом наборе данных              |
| **Серьёзность**           | Высокая: нарушается ключевое правило выборки карточек : случайная выбока                                                                                 |



##### US-002. Как _HR_ я хочу _получить список карточек с недостающими данными_ что бы _дополнить их до переноса_
Acceptance Criteria
- Получен список карточек с недостающими данными 
- Данные дополняются вручную сотрудниками HR и бухгалтерии
- Повторная выборка не выявляет карточки с недостающими данными
Приоритезация: _Must have_

==ЧЕК-ЛИСТ==

| Что проверяем                               | Ожидаемый результат                                               | Статус      |
| :------------------------------------------ | :---------------------------------------------------------------- | :---------- |

| Отсутствие карт с меткой дубля              | В выборке нет карт с меткой дубля                                 | Не пройдено |
| Сохранение внесенных данных                 | Заполненные данные сохраняются в базу данных                      | Пройдено    |

==БАГ-РЕПОРТ==

| Поле                      | Заполненный пример                                                                                                                                                                                                 |
| :------------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| **Шаги воспроизведения**  | 1. Выгрузить список карт с признаками дубликатов<br>2. Найти карту с недостающим набором обязательных данных<br>3. Поставить на карту метку дубля <br>4. Выгрузить карты с недостающим набором обязательных данных |
| **Ожидаемый результат**   | Карты с меткой дубля нет                                                                                                                                                                                           |

##### US-003 Как _HR_ я хочу _видеть списки дубликатов карточек_ что бы _устранить их перед миграцией_
Acceptance Criteria
- Выбираются записи, в которых присутствуют дубликаты карточек. Условия выборок могут меняться
- Карты проверяются. При признании дубликата ставится специальная пометка, запрещающая миграцию
- Повторная выборка не выявляет дубликатов карточек
Приоритезация: _Should have_


==ЧЕК-ЛИСТ==

| Что проверяем                   | Ожидаемый результат                                                                   | Статус      |
| :------------------------------ | :------------------------------------------------------------------------------------ | :---------- |
| Сохранение метки дубля карточки | Проставленная метка сохраняется в базе данных                                         | Пройдено    |
| Обработка метки дубля карточки  | При повторной выгрузке списка мигрируемых карт, карточки с меткой дубля не выбираются | Не пройдено |
|                                 |                                                                                       |             |

==БАГ-РЕПОРТ==

| Поле                      | Заполненный пример                                                                                                                   |
| :------------------------ | :----------------------------------------------------------------------------------------------------------------------------------- |
| **Название**              | Не обрабатывается метка дубля карточки                                                                                               |
| **Шаги воспроизведения**  | 1. Выгрузить список карт с признаками дубликатов<br>2. Поставить на карте метку дубликата<br>3. Повторно выгрузить список дубликатов |
| **Ожидаемый результат**   | При повторной выгрузке списка карт с признаками дубоикатов, карточки с меткой дубля не выгружаются                                   |

| **Серьёзность**           | Высокая: Риск неполной миграции данных                                                                                               |
